## 決定事項

### D-1. 別リポジトリとする (2026-09-10)

elevator-one に同居させず `mrmt/elevator-two` を新設する。

- one は「ルート直下 index.html」を前提に elevator-noise.com へ配信されている。同居させると
  ディレクトリ移動が必要になり、配信 URL・GitHub Pages 設定・Playwright のパスが全て変わる
- ビルド工程もモジュール分割もない単一 HTML なので、共有できるコードが実質ない。
  モノレポの主目的が成立しない
- バージョン (one は v1.4)・Issue 連番・CHANGELOG が混ざる

### D-2. one から引き継ぐもの / 捨てるもの (2026-09-10)

引き継ぐ (コードをコピーして土台にする):

- 単一 `index.html`、依存パッケージなし、ビルド工程なしという方針
- AudioContext の初期化と自動再生ポリシーへの対処
- パラメータが目標値へ時間をかけて滑らかに追従するグライド機構
- XYパッド、背景の視覚表現 (XYパッドは D-54 で廃止)
- i18n (ja / en) (D-55 で廃止)、MediaSession (ロック画面 / CarPlay)
- Playwright によるテスト構成
- MIT ライセンス

捨てる (one の音楽的な中核。two では作り直す):

- ドローン展開 (5声の持続音、緊張度による音程ベクトルの補間)
- 和声展開 (マイナー調の4和音進行)
- 16ステップシーケンサ1系統という構成

### D-3. 音楽的な照準 (2026-09-10)

Q-1 の結論。土台は minimal techno (前項 A) だが、単一ジャンルには寄せず4系統を混ぜる。

**土台 — minimal techno (主)**

- 4つ打ちを基本とする。ただし固定ではなく、適度なアレンジ (抜き・食い・ゴーストキック) を入れる
- もろに Detroit な音像は避ける。禁欲的・硬質に寄せすぎない
- コード進行は進行しすぎなくてよい。1〜2和音の反復を基調とする

**ベースライン**

- フィルタが揺れ動くベースラインは中核。ここは大きく取る
- ただし **TB-303 的なアシッドは不可**。細く単純な音色を狙わない
- 目標は Minimoog 系の厚い音。複数オシレータのデチューン積層 + サチュレーション + 深めのコンプで
  質量を出す。「みずみずしい矩形波」が基準の音色
- Ladder 型 (24dB/oct) 相当のフィルタ挙動を狙う。one のレゾナンス付きローパスより粘りを持たせる

**ハーモニー**

- Underworld "Two Months Off" 的な、明るいコードの高揚感を出せること。長い持続と反復で高揚を作る
- ジャジーなコード / ボッサ的なコード (テンション、9th・11th・13th、♭5、分数コード) を彩りとして歓迎
- 陰 (D 系 dub techno) と陽 (上記の高揚) のメリハリを持たせる

**ドラム**

- TR-808 系のアナログ発音方式のドラム音色が基準。サンプルではなく合成で作る
- シンセによるパーカッシブな音も可。ここでは FM 合成が有効
- **ベタなハイハットパターンは不可**。裏打ち固定・16分連打のような定型を避ける

**混ぜる要素**

- B (electro funk) — ときどき入れる。808 のシンコペーション、ベース主導の局面
- C (IDM) — **グリッチ要素のみ**ときどき入れる。変拍子とブレイクビーツは採らない
- D (dub techno) — 積極的に入れる。コードスタブ + 深いディレイ。陰の側を担当し、
  陽の局面との対比でメリハリを作る

**時間構造 (Q-4 の前提となる要件)**

- 数分ごとに曲調が変わる。「曲が変わる」に近い粒度の変化を持つ
- 4 / 8 / 16 小節の節目に、ブレイク、特定トラックへの強いフィルタ、
  ときにはサウンド全体へのフィルタといったイベントを置く

### D-4. 時間構造は3階層 (2026-09-10)

Q-4 の結論。

**第1層 — シーン (2〜5分)**

one の mood に相当する単位。次をまとめて決める。

- 陰陽軸の位置 (dub techno 寄り 〜 高揚するコード寄り)
- コード語彙 (単和音の反復 / 明るい持続和音 / ジャジーなテンション / ボッサ的な響き)
- ドラムキットの選択
- 参加トラックの編成
- ベースの性格 (フィルタの動き方、音域、音価)
- BPM

**第2層 — フレーズ (16小節)**

シーン内の局面。型を数種持ち、確率で辿る。

- `plateau` — 定常
- `build` — レイヤーを増やしフィルタを開く
- `break` — ドラムを抜く
- `drop` — 全体を戻す
- `dub-out` — ディレイを発振させる。D 要素の担当

型の出現重みはシーンごとに変える。陰のシーンでは `dub-out` が頻出し、
陽のシーンでは `build` → `drop` が回る、という差が自動的に付く。

**第3層 — イベント (4 / 8 小節の節目)**

第2層の型とは独立に確率で発火する単発の仕掛け。

- トラック単位のフィルタスイープ / サウンド全体へのフィルタ
- ハット抜き、キック抜きの1小節
- グリッチ (C 要素)
- ディレイのフィードバック跳ね上げ
- 逆再生風のエンベロープ

### D-5. シーン遷移は3方式を確率で選ぶ (2026-09-10)

単一の遷移方式に決めず、次の3つを持ち、遷移のたびに確率で選ぶ。同じ場所に留まらない
印象を作るのが狙い。

1. **ブレイクを挟む** — 遷移直前に 8〜16 小節のブレイクを置き、その中でキット・
   コード語彙・編成を乗り換える。「曲が変わった」がはっきり分かる
2. **無切れ目の連続変形** — one と同じく全パラメータを時間をかけて滑らかに移す。
   境目が分からない。離散的な変化 (キット交換) は伴わせない
3. **DJ ミックス風** — 16 小節かけて旧シーンと新シーンを重ね、後者のフィルタを
   開きながら入れ替える。最も自然だが2系統の同時発音が要るため実装コストが高い

実装は 1 → 2 → 3 の順に段階導入する。3 は他が動いてから着手する。

**実装後の補足** — 方式2は、回路もキットも同じ相手へ移るときにだけ選ぶことにした。
離散的に入れ替わるものが無い組み合わせでなければ、無切れ目にはならないため。
方式3で重ねるのはドラムだけに留めた。ベースと和音まで重ねると音がぶつかる。

**手でシーンを選んで遷移を打ち切るときは、方式3の2本目の経路も戻すこと** (2026-09-14)。
戻さないと、同じ小節の残りで行き先の無い並びを鳴らそうとしてキットが引けず、
例外で進行ごと止まっていた。演奏中にシーンを選ぶと「たまに止まる」の正体がこれ。

### D-6. BPM はシーンごとに変える (2026-09-10)

118〜132 の範囲でシーンごとに選ぶ。陰のシーンは遅く、陽のシーンは速くすることで
メリハリを増す。遷移中は BPM を線形に ramp して繋ぐ (方式 3 では特に必須)。

### D-7. リズムはトラックごとに別方式で生成する (2026-09-10)

Q-2 の結論。一律の確率生成やマルコフ連鎖を全トラックに回さない。土台が崩れるか
ハットがベタになるかのどちらかに落ちるため。

| トラック | 方式 |
| --- | --- |
| キック | 4つ打ちテンプレート + 変形演算子 (抜き / 16分食い / ダブル / ゴースト) |
| スネア・クラップ | 2・4拍を基本とし、シーンによってシンコペのパターン辞書へ差し替え |
| ハット (closed / open) | ユークリッドリズム E(k,16) + 揺らぎ |
| パーカッション | ユークリッド + 位相オフセット |
| ベース | 音価とフィルタの動きが主。ステップ列は度数の重み表から生成 |

**キック** — 4つ打ちを基本堅持する。普段は崩さず、8 / 16 小節の終わりやブレイク直前
といった節目でのみ、食い・抜き・ダブルを入れる。常時揺らす方式は採らない。

**ハット** — ユークリッドリズムを主軸とする。E(k,16) の k を 5 / 7 / 9 / 11 から選ぶ。
規則的だが定型ではないという中間を狙う。パラメータが k 一つで済み、シーンやフレーズに
応じて振りやすい。ここに微小なベロシティとタイミングの揺らぎを乗せる。

**パーカッション** — ポリリズム的な絡みを積極的に使う。複数トラックで互いに素な周期を
回し、長い周期で模様が変わっていく感じを出す。ただしグルーヴの軸は 4/4 に置いたままとする。

**変異** — one の mutate を継承しつつ、トラックごとに変異率を分ける。
「小節頭のキックは変異させない」のような不変条件を置き、土台を守る。

### D-8. ハーモニーは3つの独立した回路として持つ (2026-09-10)

Q-6 の方針。elevator-one でドローン展開とベルリン・スクール的シーケンサが別回路として
存在したのと同じ形を採る。D-3 で挙げた3つのコード語彙を、ひとつの汎用和音生成器の
パラメータ違いとして扱わず、それぞれ独立した回路として実装する。

- **スタブ回路** — dub techno の陰を担当。単和音を短く刺し、深いディレイとリバーブへ送る
- **持続回路** — Two Months Off 的な高揚を担当。明るい和音を長く伸ばす
- **ジャズ / ボッサ回路** — 彩りを担当。テンションを含む和音を扱う

3つが同時に鳴ることは基本的に想定しない。シーンがどれを使うかを選ぶ。
ただし同時発音を禁止はせず、遷移中や特殊なシーンでの重なりは許す。

### D-9. 各ハーモニー回路の設計 (2026-09-10)

Q-6 の結論。

**スタブ回路 (陰 / dub techno)**

- 和音は m7 / m9 を1〜2個のみ持ち、進行しない
- 裏拍 (8分の裏、または16分の食い) に短く刺す
- 原音はほとんど出さず、ディレイへのセンドを主とする。ディレイのフィードバックと
  フィルタが表情の全て。elevator-one のディレイ資産をそのまま活かす
- 第2層の `dub-out` 型では発振寸前までフィードバックを上げる

**持続回路 (陽 / 高揚)**

- 和音は add9 / sus2 中心。進行は I ⇄ IV、I ⇄ vi の緩い往復を 8 または 16 小節周期で
- 高揚は**レイヤー累積**で作る。16小節ごとに層が1枚増える
  (オクターブ上のパッド → アルペジオ → 高域のリフ)。フィルタ開きは補助に留め、
  主役にはしない。両方を強くかけると安っぽくなるため
- 天井に達したら第2層の `drop` で一度剥がし、再び積み直す

**ジャズ / ボッサ回路 (彩り)**

- 和音は maj9 / m11 / 13 / ♭9 など。ボイシングが本体なので、ルートを省いて
  3rd と 7th にテンションを足し、中音域へ密集させる
- 音色はエレピ的なもの。進行は ii-V や循環を緩く回す
- **主役シーンと差し込みの両方を持つ**。他2回路と同格で数分間の主役シーンを取ることもあれば、
  他回路のシーンへ短く差し込む彩りとしても登場する

**調性**

- キーはシーンごとに変える。遷移でキーも乗り換えることで「曲が変わった」感を強める
- 移動先は五度圏で近い調を選び、飛びすぎないようにする

### D-10. 音源の合成方式 (2026-09-10)

Q-3 の結論。単一ファイル方針を守るため、すべて自前合成とする。サンプルは持たない。

**ベース (最重要)**

- 矩形波3基を ±7cent 程度でデチューンし、1オクターブ下のサブ矩形波を足す
- WaveShaper で軽く飽和させたあと、フィルタを通し、深めのコンプ (ratio 4:1 程度) で
  質量を出す。「みずみずしい矩形波」の質はデチューン量とサチュレーションの強さで決まる
- フィルタは **AudioWorklet で Ladder 型 (24dB/oct) を実装する**。Blob URL 経由で
  読み込めば単一ファイル方針は保てる。BiquadFilter の多段近似では、レゾナンスを
  上げたときの粘りと飽和が出ず淡白になる。ベースが two の中核なのでここにコストを割く

**ドラム (TR-808 系)**

| 音 | 合成方式 |
| --- | --- |
| BD | 正弦波のピッチ落ち + 冒頭の短いクリック |
| SD | 正弦波2基 + ノイズ |
| HH | 矩形波6基を非整数比で重ねてバンドパス |
| CY | 同じく矩形波群 + 長い減衰 |
| CB | 矩形波2基 |
| Tom / Rim | 正弦波 + 短いエンベロープ |

これに加え、パーカッションには FM 合成の音を用いる (D-3)。

**和音の音色**

- 持続回路 — 鋸波の多重デチューン + コーラス
- ジャズ / ボッサ回路 — FM によるエレピ (Rhodes 系のアルゴリズム)
- スタブ回路 — 鋸波に短いエンベロープ

### D-11. 操作パラメータ (2026-09-10)

Q-5 の結論。one の7スライダーをそのままは引き継がない。「緊張」(協和⇄不協和の補間) は
D-9 の3回路構成に対応物がなく、「ゆらぎ」「ざらつき」は two では drive と glitch に吸収される。

**XY パッド** (D-54 で廃止し、2軸ともスライダーにした)

- 横軸 = **陰陽**。dub 寄り 〜 高揚寄り。D-3 以降の中心概念を直接手で動かせるようにする
- 縦軸 = **密度**。トラック数とステップ密度

one と同じく、目標と現在地を分けて表示し、実際の音は遅れて追いかける。

**スライダー**

| 名称 | 内容 | 由来 |
| --- | --- | --- |
| 音量 / volume | 出力音量 | one |
| 重さ / weight | ベースとキックの量・音域 | one |
| 押し出し / drive | サチュレーションとコンプの深さ。D-10 の厚みを直接制御する | two 固有 |
| 空間 / space | リバーブとディレイの量 | one |
| グリッチ / glitch | 第3層イベントのうちグリッチ系の発火率 | two 固有 |
| 展開 / evolution | シーン長とフレーズ遷移の速さ。one の「推移時間」の置き換え | two 固有 |
| 変異 / mutate | リズムの書き換え確率 | one |

**BPM**

スライダーで中心値を指定し、D-6 のシーンごとの自動選択はその前後で動く。
自動性を残したまま、聴き手が望む速さへ寄せられるようにする。

**シーン操作**

次の2つを両方持つ。

- **「次へ」ボタン** — 今のシーンを打ち切って次へ進む。「飽きた」を伝える手段
- **シーン一覧からの選択** — one の mood プリセットと同じく、名前付きのシーンを選べる

後者があるため、シーンは完全な自動生成ではなく**名前付きの定義を持つ**。
定義が骨格 (使用する回路、陰陽の位置、コード語彙、キット、BPM 帯) を与え、
その内側を自動生成が埋める形とする。one の mood と同じ考え方。

### D-12. シーンは14種、定義は SCENES.md に置く (2026-09-10)

主回路と陰陽で4群に分け、計14種のシーンを定義する。詳細は [SCENES.md](SCENES.md)。

- スタブ回路 (陰) — 潜行 / 苔 / 霜 / 鼓動
- 持続回路 (陽) — 遠望 / 曙 / 陽炎 / 疾走 / 祝祭
- ジャズ / ボッサ回路 (彩り) — 微睡 / 夕暮 / 硝子
- electro funk — 跳躍 / 鋼

命名は elevator-one の `PRESETS` に倣い、漢字1〜2文字 + 英語スラッグとする。
実装は4群から1つずつ (潜行 / 曙 / 夕暮 / 跳躍) 作って鳴りの差を確認し、残りを埋める。

### D-13. 次のシーンは陰陽の長周期の波で選ぶ (2026-09-10)

シーンをランダムに引かず、陰 → 陽 → 陰 を 20〜40 分かけて往復する波を内部に持ち、
波の現在位置に近い陰陽値のシーンを選ぶ。長く聴いたときに大きな呼吸が見えるようにするため。

- 波の周期そのものにも揺らぎを持たせ、毎回同じ形にはしない
- 同じシーンの連続は避ける。近い位置に複数該当する場合は直近に出ていない方を優先する
- D-11 の「次へ」ボタンは波を進めて次のシーンを引く。一覧から選んだ場合は、
  そのシーンの陰陽値へ波の位置を移してから続きを進める

### D-14. 並びは種で決め、反復を保つ (2026-09-10)

実装中に決めた。並びを小節ごとに引き直すと、ミニマルに要る反復が出ず、
毎小節ばらばらの模様になってしまう。

- 並びは疑似乱数の**種**から決める。種が同じなら同じ並びが出る
- 種が変わるのは、シーンが切り替わったとき、フレーズ型が変わったとき、
  変異が当たったときだけ
- 偶数小節と奇数小節で種をずらし、2小節でひと組の顔を持たせる

「変異」スライダーは、この種を引き直す確率を動かすものと位置づける。

### D-15. ディレイのタップは16分のグリッドに乗せる (2026-09-10)

elevator-one は付点8分とその半端な返しという組み合わせだったが、two はビートに
乗るので、グリッドから外れた返しは打点を濁らせる。16分3つと16分5つを使う。
どちらもグリッド上にあり、互いに素なので返しが拍とずれ続け、dub 的な絡みになる。

### D-16. 「次へ」も同じブレイク遷移を通す (2026-09-10)

実装中に決めた。D-11 の「次へ」ボタンを瞬時の切り替えにすると、自動の切り替えとは
別の乗り換え方がもう一つ増えてしまう。同じ `startTransition()` を通し、
ブレイクを挟んでから乗り換える。

ただし押した手応えが要るので、ブレイクの長さは自動の切り替え (8小節) の半分の
4小節にする。止まっている間に押した場合は、鳴っていないので即座に切り替える。

D-62 で、押してから乗り換わるまで next が点滅するようにした。

### D-17. ベースは和音のルート音を基本にする (2026-09-10)

聴いた結果の指摘から。ベースが音階だけを見て度数を引いていたため、
鳴っている和音と関係のない旋律になっていた。

- 度数はいま鳴っている和音の構成音から引く。ルートを最も厚く、5度がそれに次ぐ
- 小節頭は必ずルート
- 12%の確率で和音から逸れるが、音階の中から選ぶので調からは外れない

### D-18. ベースの矩形波はパルス幅変調で作る (2026-09-10)

同じく聴いた結果から。デチューンだけでは厚みが足りなかった。

- 矩形波を1本のオシレータでは作らず、鋸波とその遅延の差で作る。
  遅延の長さがそのままパルス幅になるので、そこを LFO で揺らせば
  pulse width modulation になる
- duty はおおよそ 25〜75% の間をゆっくり行き来する
- フィルタ包絡は、頭を大きく開けてから短い時間で閉じる。
  長さより落差を優先する。ここが粘りを決める

### D-19. ベースは動きすぎない (2026-09-10)

聴いた結果の指摘から。D-17 で和音には従うようになったが、打点ごとに度数を
引き直していたため旋律が動きすぎた。

- ルート以外の音は**1小節にひとつだけ**選び、それを使い回す
- ルートから離れる頻度は陰でおよそ10%、陽と electro funk で最大およそ40%
- オクターブ上げは小節の最後の打点でのみ、しかも低い確率で起きる

結果として、ベースは和音が変わるまで同じ音を鳴らし続け、和音が動いたときに
一緒に動く。旋律を作るトラックではなく、和音の足として扱う。

### D-20. 並びが切り替わる前の小節にオカズを置く (2026-09-10)

聴いた結果の要望から。8小節の折り返しの直前と、遷移に入る直前の小節に置く。

- 小節の終わりから4・6・8ステップぶんを使う。タム主体かスネア主体かを引く
- タムは音程を下げながら並べ、強さは終わりに向かって増す
- 35%の確率で次の小節の頭へはみ出す。折り返しの頭には60%でシンバルを置く

### D-21. 16分のシーケンスを足す (2026-09-10)

同じく要望から。ディケイの短いアナログシンセの音で16分を刻む層。

- 音色は鋸波が基本で、25%の確率で矩形波・三角波・細いパルスへ差し替わる
- 1音ごとにフィルタを叩いて短く閉じる。ディケイは16分ひとつぶんより少し長い程度
- ベースと同じく動きすぎないよう、1小節で使う音は和音の構成音から2〜3個に絞る
- **専用のステレオディレイを持つ**。左右で16分3つと5つ、返しを互いに送り合う
  ping-pong 型。`build` の局面で最も深くなり、`drop`、`dub-out` と続く

### D-22. エレピは硬質・金属質に寄せる (2026-09-10) — 取り下げ (D-40)

聴いた結果の指摘から。正弦の2倍音で変調するだけでは柔らかすぎた。

- 1倍の変調を別に足して胴を支える

### D-23. 和音の量を一段下げる (2026-09-10)

### D-24. ブレイクは長くて1小節 (2026-09-10)

### D-32. XYパッドの背景に YouTube の動画を流す (2026-09-11) — 取り下げ (D-60)

いま鳴っているシーンの英語名で YouTube を検索し、改変を許すライセンスの動画を
音無しで背景に流す。4小節ごとに差し替え、そのつどクロスフェードする。

**ライセンス** — YouTube が付けられる Creative Commons は CC BY 3.0 のみで、
これは改変を許す。検索は `videoLicense=creativeCommon` と `videoEmbeddable=true` で
絞る。CC BY には表示義務があるので、題名と制作者を画面に出す。

**APIキー** — ユーザーが画面から入れ、このブラウザにだけ保存する (`localStorage`)。
リポジトリには持たない。public リポジトリに直書きすると誰にでも使われ、
クォータを消費されるため。キーが無ければ一切通信せず、これまでどおりの背景になる。

**通信** — この機能を使うときだけ、two は初めてネットワークに繋がる。
IFrame Player API の読み込みと検索の2つ。`file://` から開くと検索が CORS で通らないので、
動画を使うなら HTTP で配信する必要がある。

**クォータ** — 検索は1回100単位、既定の1日あたりの上限は1万単位。
シーンごとの結果を1日ぶん `localStorage` に取っておき、同じシーンでは引き直さない。

**利用規約** — YouTube はプレイヤーを覆うことを禁じている。背景として敷き、
上に十字やランプや文字を重ねるこの使い方は厳密には抵触しうる。
手元で鳴らすぶんには問題になりにくいが、公開する場合は考慮が要る。

### D-33. 検索語を絞り込む (2026-09-11) — 取り下げ (D-60)

シーンの英語名だけでは一般的すぎて、結果が背景に使えないものばかりになる
(`gear` で自動車、`dash` でドライブレコーダー、といった具合)。次の4つを重ねる。

- **シーンの性格を語に落として添える** — docs/SCENES.md に書いた性格から起こす。
  例: 潜行 → `submerge underwater deep dark slow`
- **全シーン共通で `footage` を足す** — 素材寄りの動画に寄せる
- **`videoDuration=long`** — 20分以上に絞る。途中から流しても絵が続く
- **`order=viewCount`** — 関連度順より当たり外れが少ない

長さで絞ると何も見つからないシーンがありうるので、結果が空のときだけ
長さの条件を外して引き直す。この2回目は結果が無いときにしか起きない。

### D-34. コード弾きに連打のバリエーションを加える (2026-09-11)

持続する音色だけでなく、サステインを持たない短い和音を連打する形も持つ。

- ディケイのみ (約85ms) の和音を8分を基本に置き、28%の確率で16分の返しを足す
- **専用のステレオディレイ**へ送る。左右で16分3つと5つ、返しを互いに送り合う
  ping-pong 型。原音は45%しか出さず、返しのほうが多く鳴る
- 連打のときは持続音にあたる下2層を止める。アルペジオと高域リフはそのまま乗る
- 出やすさはシーンごとに `chop` として持つ。火花は必ず連打、祝祭は必ず持続、
  跳躍・鋼・疾走は半々、歯車は0.6、曙は0.3。他のシーンは持続のみ

シーンごとの値にしたのは、確率だけだとテストで確かめられないため。
必ず連打になるシーンと必ず持続になるシーンを両端に置いてある。

### D-35. 検索の消費を抑える (2026-09-11) — 取り下げ (D-60)

`search.list` は1回100単位、`videos.list` は1単位。ただし `videos.list` は
ID を渡して引くもので、語からの検索はできないので、検索そのものは置き換えられない。
そこで役割を分ける。

- **一覧を取り直す間隔を24時間から30日へ延ばす**。検索が走るのは
  シーンごとに月1回で足りる
- **生き死にと長さの確認は `videos.list` に任せる** (1日1回、1単位)。
  埋め込めなくなった動画、非公開になった動画、ライセンスが変わった動画を落とす。
  長く取っておくぶん、この手入れが要る
- 併せて動画の長さが分かるので、頭と終わりを避けた位置から流せる

これで1シーンあたりの消費は、月100単位 + 1日1単位になる。
14シーンすべてを毎日使っても月に 1400 + 420 = 1820単位で、
1日の上限1万単位に対して十分に低い。以前は14シーンで毎日1400単位だった。

さらに減らすなら、語で探すのをやめて CC BY のプレイリストをシーンごとに決め打ちし、
`playlistItems.list` (1単位) で引く手がある。検索が完全に不要になる代わり、
プレイリストを人が選ぶ必要がある。

### D-36. XYパッドの背景にオシロスコープを置く (2026-09-11)

出力の最終段から `AnalyserNode` へ分岐し、いま出ている波形をそのまま
XYパッドの背景に描く。音は通すだけで何も変えない。

上りのゼロ交差を探して起点にするので、波形が横に流れず、その場で形が変わる。
色はテーマのアクセント色 (`--scope`) を使う。描く先は D-54 でスライダー卓の背面に移り、D-61 で monitor の帯に移った。

### D-37. UIのテーマを3つ持つ (2026-09-11)

`html[data-theme]` と CSS 変数で切り替える。既定は属性を付けず `:root` がそのまま効く。
選んだテーマは `localStorage` に保存する。

- **既定 (sea)** — elevator-one から引き継いだ海の色
- **TE (ミニマル & インダストリアル)** — アルミ削り出しの明るい面。等間隔グリッドと
  極細の罫線、工業用の字面 (モノスペース)、原色のオレンジ・イエロー・シアンを要所だけ。
  表示部は階調を落とした面に横縞を掛けて液晶に見せる
- **EK (ダーク & サイバネティクス)** — 漆黒の筐体に単色 (イエロー) の高輝度表示。
  ステップ列を16個の正方形キースイッチにし、点いている位置はバックライト風に光る。
  各セクションをシルク印刷のように細い線で囲み、見出しに太いキャプションを付ける
パッドの下地はテーマが `--pad-a` / `--pad-b` で持つ。既定はこれを持たないので、
これまでどおり陰陽から色相を計算する。

当初は ER (パッチング & シグナルフロー) を加えた4つだったが、
聴き手の判断で廃止した (2026-09-11)。ブロック間をパッチケーブルで結ぶ作りで、
端子はブロックの内側に入れないとケーブルが細い輪になる、という知見だけ残しておく。

**その後 EK 固定にし、切り替えそのものを廃止した (2026-09-12)。**
EK の規則は基底規則より後ろに書かれていたので、`html[data-theme="ek"]` の前置きを
外して基底へ畳むだけで同じ見た目になった (同じ詳細度なら後勝ち)。
既定 (sea) と TE の規則、`localStorage` への保存、選択のボタンは削除した。

パッドの下地色と波形の色は CSS 変数のまま残っている。読み直す必要がなくなったので、
起動時に `readLook()` が1度だけ拾う。`scopeColorCache` の宣言より前に置かれた
関数なので、呼び出しは初期化の列から行う。

**canvas に `z-index` を与えたら、読み出しのオーバーレイにも積み順を明示すること。**
片方だけに指定すると、オーバーレイが canvas の下に潜って見えなくなる。

### D-38. インダストリアル・ノイズを重ねる (2026-09-11)

小節に乗らない周期で回る打点の層。ドラムとは別に持つ。

**周期** — 16分5〜15個、または8分5〜7個。16分に換算した長さで回し、通し番号
(`bar*16+step`) で位置を決めるので、小節をまたぐたびに位置がずれてポリリズムになる。
ただし **16の約数になる長さ (16分8個) は引き直す**。それだと小節の半分にそのまま
乗ってしまい、ポリリズムにならないため。並びには休符を含む (各位置35%が休み)。

**音色** — 1音ごとに不規則に振る。素材 (ノイズ / 金属質の倍音列)、再生速度、
フィルタの種類 (バンドパス / ハイパス) と帯域と Q、減衰の長さを毎回引き直す。
30%の確率で再生速度を落として崩れ落ちるようにし、35%の確率でフィルタを掃引する。

**ステレオ** — 70%は左右それぞれ独立した周期を持つ (別々の長さ・別々の並び)。
30%はどちらか片側だけに出す。

**出現率** — シーンに入るたびに引く。スタブ / 陰 0.6、ジャズ / ボッサ 0.2、
electro funk 0.3、持続 / 陽 0.2。

いま何が回っているかは進行表示に `ノイズ 11/14` のように出る (左右の周期)。
片側だけのときは数字がひとつになる。

### D-39. ベースが疎な小節はフェーザーで補う (2026-09-11)

1小節のベースの音符数が5未満のとき、単調さを補うためにフェーザーを掛ける。
その代わり量を1割下げる。

- ベース専用のフェーザーを持つ (全域通過4段 + 0.15Hz の LFO)。
  D-28 の全体に掛かるフェーザーとは別で、イベントとは無関係に動く
- 掛かるのは音符数が 1〜4 の小節。ブレイクで音が無い小節には掛けない
- 掛かっている小節では `bassBus` の量を 0.9 倍する

いまの小節の音符数と掛かっているかどうかは、進行表示に `ベース 2 +フェーザー`
のように出る。

あわせてインダストリアル・ノイズ (D-38) の量を上げた
(`.5+密度*.4` → `.95+密度*.6`)。

### D-40. エレピを Juno-106 系の矩形波の音に作り直す (2026-09-11)

D-22 で FM の金属質な音に寄せたが、聴いた結果それも違うという判断になった。
**D-22 は取り下げ**、Juno-106 のような、みずみずしい矩形波の音に作り直す。

- **DCO** — パルス波を鋸波とその遅延の差で作り、パルス幅を LFO (0.25〜0.8Hz) で
  揺らす。そこへ鋸を薄く重ねて芯を出し、1オクターブ下のサブ矩形 (D-27) を足す
- **VCF** — ローパス2段 (24dB 相当)。頭で開いてから落ち着く
- **VCA** — 立ち上がりを速く、少し落ちてから伸びる
- **コーラス** — 4.2ms と 7.1ms の短いディレイを 0.62Hz / 0.93Hz で揺らし、
  左右に振って原音と足す。厚みとうねりはここで作るので、音そのものは素のまま出す

FM の変調と、トーンバーを叩く金属質の重ねは取り除いた。

**音源の部分は D-68 で取り下げた** (Rhodes 系の FM に作り直した)。コーラスはそのまま使っている。

### D-41. エレピの立ち下がりを鋭くする (2026-09-11)

D-40 の音を聴いた結果、伸びすぎて歯切れが悪かった。

- サブ矩形の量を 0.40 → 0.58 へ上げる
- ディケイを短くし、最後は直線で切って立ち下がりを鋭くする
  (減衰は音価の18%、最大110ms。最後の20msは直線)
- **フィルタも同じ速さで閉じる**。包絡と別の時定数で開いたままだと、
  音が切れたあとも明るさだけが残って歯切れが出ない。
  音が消えるのと同じ時刻に閉じきるところまで詰める
- 和音の長さを 0.9 秒から 0.30 秒へ詰める
- 音が短くなったぶん量が減るので、`epBus` を 0.5 → 0.72 へ上げて釣り合いを取る

### D-42. 音程が動かない小節はベースのフィルタを揺らす (2026-09-11)

D-19 / D-30 でベースはルートを踏み続ける形にしたので、ほとんどの小節は
音程が動かない。そのままだと単調になるため、1小節に出る音程が2種類以下のとき、
**1音ごとにフィルタの開き幅と落ち着き先、それにレゾナンスを振る**。

- 開き幅は 3〜15倍にアクセントと押し出しを足したもの
- 落ち着き先も 0.3〜3.4 倍に振る
- **落ち着いたあとも動かし続ける**。1音の中で50〜220msごとに行き先を引き直し、
  二度三度と向きを変える
- レゾナンスは 1.8〜4.15 の間で1音ごとに引き直す (上限は 4.2)。発振寸前まで
  上がる音も混ざる。長い音では音の途中でもう一度振る。
  揺らしている間、`apply()` 側はレゾナンスに触らない (取り合いになるため)
- うねりの LFO の深さも、揺らしている間は3倍ほどに広げる

はじめは控えめな幅にしていたが、聴いた結果まったく足りず、上の値まで広げた
(2026-09-11)。

あわせてベース全体の量を下げた (`.55+重さ*.6` → `.45+重さ*.5`)。

### D-44. 再生開始は XYパッドの中央に大きく置く (2026-09-11, Issue #1)

- 止まっている間だけ出し、鳴っている間は消す

### D-45. 見つからないときは検索語を減らして引き直す (2026-09-11) — 取り下げ (D-60)

D-33 で足したのは「長さの条件を外して引き直す」1段だけで、**検索語は減らして
いなかった**。語を6つ並べたうえ CC BY と埋め込み可で絞るので、在庫の薄いシーンでは
そのまま「見つからなかった」で終わっていた。

上から順に試し、結果が出たところで止める。

1. シーン名 + 性格語 + `footage`、長さ20分以上
2. 同じ語、長さの条件なし
3. 性格語を2つまでに減らす、長さの条件なし
4. シーン名 + `footage` だけ、長さの条件なし
5. シーン名だけ、長さの条件なし

1回100単位なので、緩め方は5段までに留める。すべて空振りしたシーンは
6時間だけ「見つからなかった」ことを覚えておき、そのあいだは引き直さない。
毎回5回引くとクォータを食うため。

**それでも空振りしたときは、前のシーンで使っていた一覧をそのまま流し続ける。**
背景が止まるより、合っていない絵でも動いているほうがましなため。
表示は「見つからず、前のシーンの動画を流している」に変わる。

「見つからなかった」という記録は、背景のトグルを一度切って入れ直すと消える。
探し直したいときの手段になる。

### D-46. 動画の再生位置と速度を振る (2026-09-11, Issue #2) — 取り下げ (D-60)

  それ以下なら前半から)。長さが分からないときは 15〜180秒に広く振る
- **再生速度** — 40% 等速 / 40% 半速 / 20% 倍速

長さは `videos.list` の確認 (D-35) で分かる。確認が済んでいない一覧を使うときに

### D-47. オカズをさらに崩し、ハットに32分を混ぜる (2026-09-11)

**オカズ (D-20)** — 長さ・休符・音程の並びが毎回ほぼ同じで、崩れ方が足りなかった。

- 長さを 4/6/8 の3択から 3〜10 ステップへ
- 休符の出やすさをオカズごとに引き直す (12〜46%)。空く場所が毎回変わる
- 音程は下り基調のままだが、2割ほどは跳ね上がる。一直線に並ばない
- 強さにも揺らぎを乗せる
- 22%の確率で32分の詰めを足す

**ハット (D-7)** — 13%の確率 (`build` の局面では20%) で、その打点の直後に
32分を1つ足す。ユークリッドの並びに定型でない細かさが混ざる。

この2つのぶんだけ、打点が16分の格子から外れる。テストは16分への整列を
0.8以上、32分まで含めた整列を0.95以上として両方を見る。

### D-48. キラキラした音のリフを足す (2026-09-12)

常時鳴る層ばかりで、数分聴いたときに「ここだ」と耳を引く短い合図が無かった。
ハーモニー3回路 (D-9) はどれも和音の塊として鳴り続けるため、この役は担えない。

4番目の独立した回路として持つ。汎用生成器の設定違いにはしない (D-8 と同じ理由)。

**音色** — 鋸波2基 (デチューン ±13〜24 cent) と矩形波1基で厚みを出し、
速さの違う2本の LFO を全基の `detune` へ共通で掛けて濁らせる
(4〜9Hz と 0.7〜2.3Hz、深さは1音ごとに引き直す)。うねりが周期的に揃わないので、
和音の構成音だけを弾いても濁りが残る。後段は Juno のコーラス (D-40) と同じ作り。
**4フィート** (midi 70〜89 へ畳む)。
アタック 3ms、ディケイ 0.18〜0.30 秒、サスティンなし。フィルタも同じ速さで開いて閉じる。
リバーブとディレイの両方へ送る。

**これに FM のベルを重ねる。** 1オクターブ上を芯にして、非整数比 (1.41 / 2.76 / 3.5)
で変調する。倍音が整数列から外れるので金属質になる。変調指数は落としながら鳴らし、
倍音が減っていくのが鐘らしさになる。ローパスは通さず VCA の後ろへ直に入れる
(閉じると芯が消えるため)。減衰は鋸・矩形の2.7倍まで取って、消えぎわに響きだけ残す。

量は回路の出口で測ったピークが 0.17 ほど。一度は 0.36 まで上げたが、
他の層を押しのけて前に出すぎたので半分に戻した。天井に張り付くサンプルは出ない。

**出現箇所** — 4小節区間のうち **4小節め**、たまに **2小節め** (62% / 38%)。
区間の頭で出すかどうかと、出す小節をまとめて決める。

**旋律** — 和音の構成音だけで作る4分音符3〜5個。順次進行を主とし、2割ほど跳ぶ。
5個めは次の小節の頭へはみ出す。

**出現率** — 毎分1〜2回。4小節区間は `960/bpm` 秒なので、区間ごとの確率を
BPM から逆算する。こうすると拍が振れても毎分の回数が保たれる。
加えて前回から22秒未満なら出さない。確率だけだと固まって出ることがあり、
それでは「たまに出る」にならないため。

**この下限が直後の何区間かを塞ぐので、確率にはそのぶんを織り込む。**
素の確率のままだと実測で毎分0.8回まで落ち、目標を割った。
塞がれる区間の数 `g` を秒数から出し、`r/(1-r·g)` を確率に使う
(`r` は下限が無ければ足りる確率)。125 BPM で 0.31、実測 毎分1.4回。

ブレイクの局面では出さない。

### D-49. ダブを入れる (2026-09-12, Issue #3)

dub techno を混ぜると謳っているのに、dub 的なのは `dubout` フレーズ (ディレイを
少し深くするだけ) とスタブ回路の送りだけだった。**音を抜いてディレイだけで
持たせる**という中核の身振りが無かった。

1小節だけドラムを落とし、全体をディレイに放り込み、小節の終わりのオカズで戻す。

| 項目 | 決め |
| --- | --- |
| 出現判定 | 8小節ごと。`group==='funk'` は50%、それ以外は20% |
| 出現箇所 | 判定した範囲から4小節区間をひとつ引き、その4小節め (60%) か2小節め (40%) |
| 開始 | 小節の頭 (50%) か、途中 (ステップ 4 / 6 / 8 / 10) |
| 終了 | その小節の終わり |
| ドラム | 開始点以降ミュート。出口のオカズだけは鳴らす |
| 他トラック | 開始点以降は3割だけ残し、原音を 600Hz まで閉じる |
| ディレイ | 左右とも8分か付点8分に揃える。膨らませて切り落とす (下記) |
| 出口 | 最後の16分4個にオカズ。休符・音程・強さの振りを通常より大きく、32分も混ぜる |

**ローパスは `dry` と `mixFilter` の間に置く。** ここが要点で、リバーブと
ディレイの返しは `mixFilter` へ直に入るので、`dry` だけを閉じれば
**原音は消えても返しは生き残る**。dub でやりたいことがそのまま経路の形になる。
`mixFilter` (masterfilter イベントが使う) を閉じると返しまで消えて、ただの無音になる。

**ディレイが dub の要なので、鳴っているあいだ次第に大きくなるようにする。**
フィードバックを .82 から 1.08 まで上げて返しがむしろ増えるようにし、
出力も素の2倍から3.2倍まで上げ続ける。

そのままでは収まらないので、**小節末か次の小節の1拍終わりで切って落とす**。
小節末が 3/4、次の小節へずれるのが 1/4。ずれるほうは効かせどころなので、
たまに出るくらいでいい。フィードバックと出力を同時に 0 に置いて回りを止め、
遅延の長さぶんだけ待ってから素の量へ戻す。待たずに戻すと、線に溜まったぶんが
大きいまま1回だけ吐き出されて残響のように聞こえる。

実測では返しが 0.006 から 0.21〜0.35 まで育ち、切ったあとは 0 になる。

`apply()` が毎回ディレイの長さを 3/5 に書き戻していたので、
`evDelayUntil` のガードの中へ移した。そうしないと dub の間に間隔が戻ってしまう。

ブレイクの局面とシーン遷移中は出さない。

**当初は32小節ごとに funk 30% / 他3% だった (2026-09-12)。** 聴いた結果、
出番が少なすぎたので 8小節ごとに funk 50% / 他20% へ上げた。
125BPM だと8小節は約15秒なので、funk のシーンでは30秒に1回ほど、
他のシーンでも1分半に1回ほど出る。

### D-50. 単純なベースにたまに揺らぎを掛ける (2026-09-12)

サスティンのある音色 (D-25) は音が伸びるぶん、同じ音程が続く小節で間延びする。
D-42 の「フィルタを1音ごとに振る」はその手当てだが、動くのはフィルタだけで
音程は据わったまま。

**音程そのものを LFO で振る。** 4.5〜7.5Hz、深さ 18〜55 cent を1音ごとに引き直し、
矩形波3基とサブの `detune` へ共通で掛ける。頭は素のまま立ち上げたいので、
深さは 0 から始めて伸びはじめてから効かせる (立ち上がりの 0.18 秒まで)。

条件は2つ。

- **サスティンのある音色** — タイトな音色は伸びないので掛ける先がない
- **旋律が単純** — 音程2つ以下

ただし**このベースは設計上ほとんどの小節が単純**で、実測では音程1つが74%、
2つ以下で97%。条件は「動きすぎる小節を外す」程度しか効かない。
薄さは9%のほうが担う。

出現率は条件を満たす小節の9%。実測 208小節中21回 (0.101)。

XY パッドの下の表示に `+ビブラート` として出る。

### D-51. 太いベースはオクターブを上下させ、揺らぎを音程にも掛ける (2026-09-13)

持続する太い音色は、同じ音程が小節中に続くと平板になる。
D-19 でルートを踏み続ける形にしたので、この状態がほとんどの小節で起きる。

**オクターブを上下させる。** 持続する音色 (D-25) のとき、
直前の打点と同じ音程が続いた打点を 35% で 1オクターブ動かす。
当初は electro funk (`group==='funk'`) だけに限っていたが、
すべてのシーンで行うよう広げた (2026-09-13)。

- 8割は上げ、2割は下げる。ベースの音域 (31〜42) がもともと低く、下げると
  下がりすぎるため。さらに下げた先が midi 28 を割るなら上げる (芯が消えるため)。
  当初は上下半々だったが、聴いた結果下がりすぎたので改めた (2026-09-13)
- 小節の頭の打点は動かさない。ルートの足場として残す
- ベース専用の乱数から引くので、種が変わるまで同じ並びを繰り返す (D-30)

**音程数は音名で数える。** オクターブを動かしただけの小節が「音程が動く」扱いになると、
フィルタの揺らし (D-42) と揺らぎ (D-50) が外れてしまうため。

**フィルタを揺らしている小節では、音程にもときどき揺らぎを掛ける。**
D-50 の小節単位の9%とは別に、持続する音色で `bassWobble` が立っている小節では
1音ごとに25%で D-50 と同じ揺らぎを掛ける。フィルタだけが動いて音程が据わったまま、
という状態を崩す。1音ごとに引くので、`+ビブラート` の表示には出ない。

### D-52. リフの旋律にオクターブ下をアクセントとして混ぜる (2026-09-13)

キラキラのリフ (D-48) は4フィート (midi 70〜89) に畳んだ音だけで作るので、
旋律の起伏が音域の幅に収まってしまい、3〜5個の短い合図としては平らに聴こえる。

**頭の音と、跳んで着いた音を、50% / 40% で 1オクターブ下へ落とす。**
落とした音は midi 58〜77 に出る。旋律の形はそのままで、その音だけ重心が下がるので、
アクセントとして立つ。跳躍 (D-48 の2割) を選ぶのは、動きの大きい着地がもともと
耳を引く位置だからで、そこを補強すると旋律の輪郭に沿う。

- **続けては落とさない。** 隣り合う音を両方落とすと旋律ごと下がって、
  アクセントではなくただの移調に化ける
- 落とした音は 1.15 倍だけ強く弾く (上限 1)。フィルタは音程に追従して開くので
  (`f*2.4+400`)、下げたぶん暗くなり、同じ強さでは引っ込むため
- FM のベル (D-48) は1オクターブ上を芯にするので、落とした音では元の音域で鳴る。
  低い基音の上に元の高さの響きが乗り、アクセントでも輝きは残る

実測では音の 17%、リフ全体の 61% に1つ以上入る。旋律を先に引いてから
落とす音を決める二段構えにしたので、跳躍の判定を1音先まで見られる。

### D-53. 次のシーンは別の群を優先して選ぶ (2026-09-14)

D-13 の波は陰陽値の近さだけで次のシーンを選ぶので、隣り合う陰陽値に同じ群
(ハーモニー回路 D-8 / D-9) のシーンが並ぶ区間では、群の中を渡り歩く遷移が続く。
群が変わらないと回路もキットも据わったままで、遷移が起きたことが伝わりにくい。

**波に近い5つのうち、別の群のシーンへ 80% で渡る。** 回路とキットが同時に

- 候補の窓を3つから5つへ広げた。3つのままだと同じ群しか入らない位置があり、
  優先が効かない。窓は波から離れすぎない範囲に留めるので、D-13 の呼吸は保たれる
- **残りの2割は同じ群へ渡すが、キットまで同じ相手を先に採る。**

  シーンが出やすくなるが、偏りきる位置は無い

### D-59. mixer の音量に SOLO / MUTE を付ける (2026-09-14)

- 規則は DAW と同じ。どれかが SOLO なら SOLO 以外は無音、複数 SOLO できる。
  **MUTE は SOLO より強い** (SOLO かつ MUTE なら無音)
- **bell FM ratio には付けない。** 音量ではなく倍率で、黙らせる意味を持たないため。
  ベルを黙らせたいときは riff bell の側で行う
- **保存しない。** 聴き分けるための一時的な操作で、次に開いたときに音が欠けていると
  理由が分からないため。`reset all` でも解除する
- 無音になっている行は名前とスライダーを薄くする。ボタンは押し戻せるよう薄くしない
- 実装は個別の音量 (D-54) の読み出しを `lv()` に置き換えただけ。音の経路は変えていない。
  ドラムは次の打点から、それ以外は `apply()` の次の周回 (100ms) から効く

### D-64. シンバルを明るくする (2026-09-14)

聴いた結果、シンバルが低く濁っていた。ハイハットと同じ金属質の源 (矩形波6基、D-10) を
等速のまま、中心 5200Hz・Q 0.5 の広いバンドパスで削っていたので、源の低い倍音が抜けきっていなかった。

- 源を再生速度2倍で読み、倍音をすべて1オクターブ上げる
- バンドパスをやめ、6000Hz のハイパスで低い側を落とす
- 同じ条件で書き出して測ると、スペクトルの重心は 3.2kHz → 9.6kHz、3kHz 未満のエネルギーは 59% → 2%。
  音量 (RMS) は 0.0106 → 0.0103 とほぼ同じなので、量は変えていない
- ハイハットは同じ源を等速のままハイパスで削るので、1オクターブの違いで音色も分かれる

### D-65. 平行移動の転調 (shift) (2026-09-14)

形を保ったまま根音だけを動かす転調を、既存のすべての回路に混ぜる。強さは control の
`shift` スライダーで決め、**0 なら従来どおり** (シーンごとに五度圏で近い調へ移るだけ)。

- **主音を1箇所に集めた。** 音程を出す箇所 (和音の構成音・ベース・16分のシーケンス・表示) は
  シーンの調を直接読まず、`tonic()` = シーンの調 + 平行移動のずれ を通す。
  これで和音・ベース・シーケンス・アルペジオが揃って平行に動く
- **平行移動** — 8小節の節目 (遷移中を除く) に、確率 `shift` でずれを動かす。
  0 からは短3度・長3度の上下を主に、全音下げと4度・5度を少し混ぜて引く。
  ずれている間は半分の確率で 0 へ戻る。3度の横滑りは共通の音が少なく、場面が切り替わった感じが強い
- **盛り上げの全音上げ** — 積み上げ (build) から戻し (drop) へ抜ける頭で、確率 `shift×0.8` で調ごと全音上げる
- **ペダル** — 和音が変わるとき、確率 `shift×0.5` でベースだけ前の根音に2小節留める (D-67 で1小節に)。
  上の和音とのぶつかりが緊張を作り、ベースが動いたときにほどける
- **シーンの転調** — 確率 `shift×0.5` で、五度圏の近い調ではなく3度や短6度の遠い調へ移る
- 表示: 調の後ろに平行移動の量 (`+3` など)、ペダルの間はベースの欄に `+pedal`

### D-66. 開いた和声 (lush) (2026-09-14)

テンションの多い和音を開いた配置で置き、声部をなるべく動かさずに運ぶ和声を、e.piano 回路 (jazz) と
strings 回路 (sustain) に混ぜる。強さは control の `lush` スライダーで決め、**0 なら従来どおり**。
stab と electro funk には効かせない (短く刻む回路で、和音を伸ばさないため)。

- **判定** — シーンに入るときと16小節ごとに、確率 `lush` で開いた和声の進行を使うかを引く。
  変わったら進行ごと選び直す
- **和音の種類** — maj7#11 / mMaj9 / 7sus4(9) / m6/9 / maj13 / 4度の積み重ねを足した
- **進行** — 別の表から引き、1つの和音を8小節伸ばす (D-67 で4小節に)。型は
  「同じ種類の和音を半音ずつ下げる」「低音を据えて上の和音だけ入れ替える」「長調で短調の iv を借りる」
  「4度和音の平行移動」「根音を据えて内声だけ半音ずつ動かす」「分数コードで着地をぼかす」
- **分数コード** — 和音とは別に低音の度数を持てる。ベースはその音を踏み、分数コードの間は低音を動かさない
- **開いた配置** — 根音を低く、3度・7度を1オクターブ上、テンションをさらに上に置く。
  midi 60 未満では隣り合う音を3半音以上離し、根音は重ねない。4度和音は積んだまま
- **声部の運び** — 声部の数が同じなら、持続音を入れ替えずに各声部を前の音に一番近いオクターブへ滑らせる (約0.35秒)。
  数が違えば従来のクロスフェード
- **内声の半音の動き** — 和音ごとに確率 `lush×0.6` で内声を1つ選び、2小節ごとに半音ずつ最大3歩動かす (D-67 で1小節ごとに)
- **濁り止め** — アルペジオ・高域リフ・リフ (D-48) には、テンションを除いた基本の音だけを渡す。
  e.piano は根音を省いた開いた配置、連打とスタブは従来のまま
- **strings の音色** — 開いた和声のときは立ち上がりを 1.4 → 2.4秒にし、遅れて深くなる細いビブラート (約5Hz・6セント) を掛ける。
  値は聴いて詰める

### D-67. 和音の進行を2倍の速さにする (2026-09-14)

聴いた結果の調整。和音が変わる間隔を、すべての回路で従来の半分にした。

| 回路 | 従来 | いま |
| --- | --- | --- |
| stab | 16小節 | 8小節 |
| strings (sustain) | 8小節 | 4小節 |
| e.piano (jazz) | 4小節 | 2小節 |
| electro funk | 8小節 | 4小節 |
| 開いた和声 (D-66) | 8小節 | 4小節 |

和音の間隔を基準にしている仕掛けも同じ比率で詰めた。

- 開いた和声の内声の半音の動き (D-66) は、2小節ごと → 1小節ごと。4小節の和音の中で最大3歩動く
- ペダル (D-65) は、2小節 → 1小節

平行移動の転調 (D-65) の判定は和音ではなくフレーズの節目 (8小節) に乗っているので、変えていない。

### D-68. e.piano を Rhodes 系のエレピの音にする (2026-09-14)

聴いた結果、e.piano をもっとピアノらしくしたい。Rhodes 系のエレピに寄せ、長さは今の短さ (D-41) を保つ。

D-22 で FM の金属質な音を試して取り下げているので、今回は金属を叩く硬さではなく、
**丸い胴と、強く弾いたときだけ出る歪み (bark)** を主にした。

- **胴** — 正弦波の搬送波を、同じ周波数の正弦波 (比 1:1) で変調する。変調の深さは頭で深く、
  約60msで浅くなる。深さは強さに比例させ、弱く弾くと丸く、強く弾くと明るく歪む
- **打鍵のカチッ** — 比 14 の変調を、頭の約12msだけ弱く掛ける
- **長さ** — 立ち上がり 2ms の直線。減衰は従来どおり音価の18% (最大110ms)、最後の20msは直線で切る
- パルス波・鋸波・サブ矩形・ローパス2段 (D-40 の音源) は取り除いた。1音あたりのノードは約15 → 7
- **回路の出口は変えない。** Juno のコーラス (D-40) と、リバーブ・ディレイへの送りはそのまま
- **音量** — 同じ和音を新旧で書き出して測ると、係数1のままでは RMS が 0.0448 → 0.0663 と大きくなるので、
  発音側に係数 0.68 を掛けて 0.0451 に揃えた。スペクトルの重心は 904Hz → 560Hz で、丸い音になる

**アタックを強めてみたが、戻した (同日、聴いた結果)。** 「アタックが弱い」という指摘を受けて、1音を書き出して、
鳴り始め12msを測ると、胴との音量比は以前の音 2.70 に対して 2.99 と十分だったが、
重心が 777Hz → 457Hz と暗く、弱く聞こえる原因はこちらだった (以前の音はフィルタを大きく開けて立ち上げていた)。

- 胴の変調を深く速くした。深さ `f×(0.4+強さ×1.6)` → `f×(2.5+強さ×7)`、浅くなるまで 60ms → 25ms
- 打鍵のカチッを強く長くした。深さ `f×(0.3+強さ×0.9)` → `f×(3+強さ×8)`、12ms → 20ms
- 頭の8msだけ音量を1.6倍に持ち上げる
- 全体の RMS を揃える係数は 0.68 → 0.56
- 測定値 (強さ 0.8、1音): 鳴り始めの重心 457Hz → 1056Hz (以前の音 777Hz)、胴との音量比 2.99 → 3.12、全体の RMS は同じ。
  変調を少し浅くした組 (深さ `f×(1.5+強さ×5)`、30ms) は 919Hz・3.09 だった

聴いた結果、**オーケストラのピチカートの擦れのような音になり、ピアノから遠ざかった**ので、上の変更はすべて戻した
(いまの値は、この追記より前の段落のとおり)。

- 鳴り始めの重心を上げる方向は、変調を深くして高い倍音の雑音のような成分を足すことになり、
  ピアノの打鍵の立ち上がりとは別物になった。重心や音量比は、ピアノらしいアタックの指標にはならなかった
- アタックを立て直すなら、明るさではなく別の手がかり (打鍵の低い衝撃音、ごく短い音量の山だけ、など) を
  1つずつ試して聴いてもらう

**打鍵の低い衝撃音を足した (同日、試しているところ)。** 上の手がかりのうち1つ目だけを入れた。ほかの値は変えていない。

- 和音1つにつき1回、低い音を短く鳴らす。声部ごとに鳴らすと重なって太りすぎる
- 三角波、音程は 170Hz から 20ms で 80Hz へ落とし、約30msで消える。量は強さ×0.14 (e.piano の頭は強さ×0.18)
- e.piano の回路へ入れるので、同じコーラスを通り、個別の音量・SOLO / MUTE も e.piano と一緒に効く
- 三角波にしたのは、正弦波の音程の予約でタムを数える試験 (オカズ) に紛れさせないため
- 戻すときは `epChord()` の `epThump()` の呼び出しを外すだけでよい

**減衰を少しだけ伸ばした (同日、聴いた結果)。** e.piano の音そのものの減衰だけを変えた。

- 減衰の長さ: 音価の18% (最大110ms) → 24% (最大150ms)。e.piano の和音は音価 0.30秒なので 54ms → 72ms
- 最後の20msを直線で切ること、変調の深さの変化 (約60ms)、打鍵の衝撃音は変えていない

### D-69. タイトルの左に上の階層へのリンクを置く (2026-09-14)

画面上のタイトルの左に、エレベーターのアイコンで `../` へのリンクを置く。

- アイコンの SVG は index.html に直接埋め込む。単一ファイルの方針 (D-2) を保つため
- 塗りは `currentColor` にし、リンクの色を `--ink` にした。タイトルの文字と同じ色になる
- ヘッダーは文字の下端で揃えているので、アイコンだけ上下中央に置く

**狭い画面でヘッダーが2行に落ちた (同日、CI で発覚)。** アイコンのぶん幅が足りず、再生ボタンが2行目に落ちた。
最初はタイトルの字間を詰めて直したが、それは短いシーン名のときだけ効いていた。iPhone 14 幅で測ると、
