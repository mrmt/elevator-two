## 決定事項

### D-1. 別リポジトリとする (2026-09-10)

elevator-one に同居させず `mrmt/elevator-two` を新設する。

- one は「ルート直下 index.html」を前提に elevator-noise.com へ配信されている。同居させると
  ディレクトリ移動が必要になり、配信 URL・GitHub Pages 設定・Playwright のパスが全て変わる
- ビルド工程もモジュール分割もない単一 HTML なので、共有できるコードが実質ない。
  モノレポの主目的が成立しない
- バージョン (one は v1.4)・Issue 連番・CHANGELOG が混ざる

### D-2. one から引き継ぐもの / 捨てるもの (2026-09-10)

引き継ぐ (コードをコピーして土台にする):

- 単一 `index.html`、依存パッケージなし、ビルド工程なしという方針
- AudioContext の初期化と自動再生ポリシーへの対処
- パラメータが目標値へ時間をかけて滑らかに追従するグライド機構
- XYパッド、背景の視覚表現
- i18n (ja / en)、MediaSession (ロック画面 / CarPlay)
- Playwright によるテスト構成
- MIT ライセンス

捨てる (one の音楽的な中核。two では作り直す):

- ドローン展開 (5声の持続音、緊張度による音程ベクトルの補間)
- 和声展開 (マイナー調の4和音進行)
- 16ステップシーケンサ1系統という構成

## 検討中の論点

以下は未決。順に壁打ちしていく。

### Q-1. 「気持ちいいエレクトロ」の照準

ジャンル的にどこを狙うか。Detroit techno / minimal techno / electro funk / IDM などの
どの辺りか、あるいはその混成か。ここが決まらないと以降のパラメータ設計が定まらない。

### Q-2. リズムの生成方式

多トラック (キック / スネア / ハット / パーカッション / ベース) をどう自動生成するか。
候補: ユークリッドリズム、確率テーブル、マルコフ連鎖、これらの併用。
one の「変異確率で1小節ごとに書き換える」方式をどこまで流用するか。

### Q-3. 音源

単一ファイル方針を守るなら、808 / 909 系のドラムを自前で合成することになる。
サンプルを data URI で埋め込む案もあるが、ファイルサイズと引き換えになる。

### Q-4. 時間軸と展開

one の「漂い続ける」に対し、エレクトロは展開を要する。
16 / 32 小節単位のセクション遷移 (intro / build / drop / breakdown 相当) を
どう自動生成し、どう飽きさせないか。

### Q-5. 操作パラメータ

one の 音量 / 重さ / ゆらぎ / 緊張 / 空間 / ざらつき / 推移時間 に相当する
two 側の軸をどう定義するか。XYパッドの2軸に何を割り当てるか。
